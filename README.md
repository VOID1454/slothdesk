# SlothDesk 🦥
Less paperwork. More tea breaks.

A local training-evaluation app with deterministic assessment calculations and real local AI feedback summarisation through Ollama. No Python packages or API keys required. Python 3.10+.

## Quick start (Windows)
1. Install Python from https://www.python.org/downloads/ (enable “Add Python to PATH”).
2. Install Ollama from https://ollama.com/download and launch it.
3. Open Command Prompt and download the open-weight model once:
   ```
   ollama pull qwen2.5:1.5b
   ```
4. Extract this ZIP. Open the `slothdesk` folder and double-click `START_WINDOWS.bat`. Alternatively, run `python app.py` in that folder.
5. Open http://127.0.0.1:8765 if your browser did not open automatically.
6. Click **Try sample data**, then **Generate feedback summary**. Review the draft and download the report.

On macOS/Linux, install Python and Ollama, pull the same model, and run `python3 app.py`.
If Ollama is not running, start the desktop application or run `ollama serve` in another terminal. Refresh SlothDesk to update its status.

The initial software/model downloads require internet. Once installed, the app uses only loopback HTTP and local assets; verify offline inference on your computer by disconnecting internet and generating a new summary. Inference speed and memory needs depend on your hardware. No bundled model weights.

## Your files
Export Excel/Google Sheets tabs as **CSV UTF-8**, not PDF or XLSX. This first version accepts CSV only. Rename headers to exactly:

Pre and post (one record per participant per file):
```csv
participant_id,score,max_score
P001,7,10
P002,12,20
```
Feedback:
```csv
feedback
"The demonstration was useful, but more practice would help."
```
Use pseudonymous, stable participant IDs. Duplicate IDs are rejected; resolve repeated submissions yourself. Scores must be finite, non-negative, and no higher than a positive maximum. Blank score rows are rejected rather than guessed. Extra columns are ignored. Feedback CSV row numbers become citations: F2 refers to data on the first CSV record after the header (multiline CSV values count as one record).

## How calculations work
Scores are normalised to percentages. Only participant IDs present in BOTH files contribute to means and changes. Unmatched records are listed separately. Change means percentage points, not relative percent improvement. Compare equivalent assessments; differences do not establish causal impact. No attendance count is inferred from assessment submissions.

Synthetic sample expected result: 4 matched, 57.5% pre, 80% post, +22.5 percentage points, 3 improved, 1 unchanged. P005 and P006 are unmatched.

## Open AI at the core
The feedback narrative is generated by **Qwen2.5 1.5B**, an Apache-2.0 open-weight model, running through **Ollama**, an MIT-licensed inference runtime. No canned AI output or closed-model fallback is used. Without the model, calculations and manual report writing still work, but AI summarisation displays an explicit error.

- Model and licence: https://ollama.com/library/qwen2.5
- Runtime/source: https://github.com/ollama/ollama
- Chat API: https://docs.ollama.com/api/chat

The app source is MIT licensed. Model/runtime licences remain separate. To experiment with another LOCAL model, pull its exact tag and change MODEL in app.py. Check its licence and context needs first. Do not use cloud model tags if you require offline processing.

## Privacy and limits
The server binds only to 127.0.0.1; model requests go only to 127.0.0.1:11434, with environment proxies disabled. Host checks and a per-session request token protect write endpoints. There are no analytics, external fonts, automatic uploads, or app disk storage of input files. Data remains in browser/server memory during processing and the user-chosen report download. Ollama and OS memory/log handling are separate from the app; this is not a certified secure-erasure system.

Only feedback text and citation IDs go to the model, not participant assessment IDs. Feedback text itself can contain personal information, so remove it before import if needed. AI text is untrusted and must be reviewed against the displayed records. Prompts instruct the model to ignore embedded instructions, but this is not a guarantee against prompt injection. The model has no tools or file access through this app. HTML exports escape user/model text.

Maximum: 2,000 records per file, 2 MB total request, 2,000 characters per comment, 18,000 total feedback characters per AI summary. Oversized summaries are rejected explicitly. No silent truncation. Large batches must be split. This MVP does not ingest PDFs, OCR, XLSX, or Google Forms directly.

Reports export as standalone HTML. Open in a browser, then Print → Save as PDF. Native Word export is not included.

## Test and demo
Run `python -m unittest -v` inside the project directory.
Automated tests cover matched cohorts, invalid scores, duplicates, missing matches, normalisation, model-request construction, and feedback limits. Model integration is mocked in unit tests; a real model generation must be checked on your machine.

Suggested 60-second recording:
1. Show the local URL and model-ready indicator.
2. Load sample data and explain matched/unmatched IDs.
3. Generate feedback summary, inspect its F-number evidence references.
4. Edit one sentence, download the report, show print-to-PDF.
5. Disconnect the internet and generate again to demonstrate offline operation.
